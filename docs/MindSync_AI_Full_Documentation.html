Executive Summary & Project Overview

MindSync AI is a production-grade wellness application designed specifically for software engineers and IT professionals. It leverages state-of-the-art Random Forest machine learning models and Google Gemini LLM orchestration to predict developer burnout risks, supply context-aware habit suggestions, track moods, support AI chat coaching, and compile visual telemetry dashboards.

🎯 Problem Statement
IT professionals face uniquely high rates of burnout, stress, and sedentary lifestyles. MindSync AI addresses this by combining mood tracking, predictive ML analytics, and empathetic AI coaching into a single mobile companion.

Target Users

MindSync AI is designed for IT professionals including Software Engineers, Data Scientists, DevOps Engineers, QA Engineers, System Administrators, UI/UX Designers, and university students in computing disciplines.

  • Low Friction Logs: Allow users to log mood, sleep, water, and exercise in under 15 seconds
  • Actionable Insights: Explain wellness trends and burnout risks clearly, without complex jargon
  • Empathetic Tone: Keep copy warm and supportive, especially when displaying high burnout risks
  • Consistent Experience: Smooth navigation and readable layouts in both light and dark modes

4.2 Communication & Data Flows

A. Authentication Flow

  1. User logs in via Email/Password in the Flutter App
  2. Firebase Authentication registers the session, generating a short-lived JSON Web Token (ID Token)
  3. Flutter stores the ID Token locally in a Hive encrypted box
  4. For every backend query, a custom Dio interceptor inserts Authorization: Bearer <ID_Token>
  5. FastAPI verifies the token against Google's public JWKS certificates, retrieving the verified user ID (uid)

B. Machine Learning Inference Flow

  1. Flutter aggregates the user's latest 7-day health metrics and fires a POST to /api/predict/burnout
  2. FastAPI validates parameters via Pydantic schemas
  3. Random Forest model computes prediction score, risk category, and class confidence
  4. SHAP value matrices isolate the top three contributing factors
  5. Results are logged to Firestore and returned to the client

C. AI Conversational Flow

  1. User types a query in the chat console
  2. Flutter sends message + session ID to FastAPI /api/chat/message
  3. FastAPI retrieves user profile, mood logs, sleep metrics, and conversational memory
  4. Backend constructs a structured prompt and submits to Gemini API (gemini-1.5-flash)
  5. Gemini generates a tailored wellness suggestion, which is parsed, logged, and returned

Layer Responsibilities

  • Presentation Layer: Renders UI and handles user interaction. Widgets react to Riverpod Provider state changes. Providers call Domain Use Cases.
  • Domain Layer: Independent core with clean Entities, Use Cases, and abstract Repository Interfaces. Zero dependencies on frameworks.
  • Data Layer: Implements repository contracts, maps network payloads to models, decides between Hive (local) and API endpoints (remote).
  • Core Layer: Shared configurations – themes, routing, constants, validation, and failure types.
  • Dependency Injection: Managed declaratively using Riverpod, maintaining singletons where needed.

9.3 Data Preparation

  • Imputation: Missing values default to historical user averages
  • Outlier Clamping: Values outside standard distributions are clamped (e.g., sleep > 18h, steps > 40k)
  • Target Encoding: 0 → Low Risk, 1 → Medium Risk, 2 → High Risk
  • Scaling: Robust scaling on steps and exercise minutes to avoid variance bias

9.4 Model Training & Comparison

AlgorithmTypeSelection Status
Logistic RegressionLinear baseline modelBaseline comparator
Decision TreeNon-linear, single treeOverfitting prone
Random ForestEnsemble (multiple trees)✅ Selected – Best accuracy & generalization
📊 Performance Targets
Primary Metric: F1-score (macro-averaged) • Target Accuracy ≥ 85% • F1-score ≥ 0.80 • Cross-validation: cv=5

9.5 Explainable AI (SHAP)

SHAP (SHapley Additive exPlanations) computes individual feature contributions. When the model flags High Risk, the backend extracts the top three SHAP values and returns them as importantFactors — e.g., "Low sleep is contributing most to your risk score."

9.6 Deployment

  • Model serialized to backend/app/ml/models/burnout_model.pkl via Joblib
  • FastAPI loads the model into memory during startup
  • Inference executes in under 50 milliseconds

10.2 Prompt Engineering Strategy

System Guidelines
"You are MindSync AI, an empathetic wellness coach for IT professionals. You suggest healthy boundaries, stress reduction habits, and digital breaks. You do not offer clinical diagnosis. Maintain answers under 150 words. Adopt a warm, professional tone."

Context Ingestion: The prompt includes active profile variables — "The user is a Software Engineer, aged 29. Their average stress level over the last 3 days was 8/10. Sleep averaged 5.5 hours."

10.3 Conversation Memory

FastAPI retains the last 10 message documents under the active sub-collection to prevent token bloat while maintaining context-aware responses.

10.4 Safety Filters & Key Security

  • Content Restrictions: API safety configurations flag and reject queries relating to self-harm, hate speech, or clinical queries
  • Prompt Injection Defense: Sanitization module filters blacklisted injection patterns (e.g., "ignore prior instructions", "system override"). Attacks return 400 Bad Request
  • Medical Disclaimer: Every output appends: "Disclaimer: MindSync is a wellness companion and does not replace medical advice."

Context-Aware Recommendation Engine

MindSync AI uses multi-source context inputs to deliver personalized, situation-aware recommendations.

11.1 Decision Logic

ConditionAction
Weather = Rainy AND Stress ≥ 7Suggest indoor recommendations (desk stretches, muscle relaxation)
Weather = Clear AND Steps ≤ 3000 AND Time = 14:00Suggest 15-minute outdoor walk
Time = Late evening AND Sleep < 6hTrigger wind-down notification
Burnout Risk = HighPrioritize stress-reduction, bypass intense activity targets

11.2 Context Inputs

  • Time of Day: Adjusts suggestion categories (morning activity vs. evening wind-down)
  • Weather Data: OpenWeather API drives indoor/outdoor suggestion routing
  • Location: GPS for broad location attributes
  • Burnout Risk Level: ML prediction re-ranks recommendation priority
  • Mood History: Recent trends influence suggestion tone and type
